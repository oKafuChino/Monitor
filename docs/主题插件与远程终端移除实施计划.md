## 0. 用户决定与范围优先级

用户原话：

> 探针主要用于我个人使用，可以移除对自定义主题和插件的支持；远程 SSH 控制出于安全考虑可以删除，其余先不移除。

此要求覆盖之前报告中更大范围的精简建议。执行 agent 不得以“轻量化”为理由顺便删除其他功能，也不得把前次报告中的建议视为本次授权。

### 0.1 本计划采用的明确边界

| 项目 | 本轮处理 |
| --- | --- |
| 外部/自定义主题包 | 删除安装、导入、更新、切换、配置页面扩展、市场及任意目录资源加载能力 |
| 插件 | 删除安装、启停、市场、配置/公开页面、动态菜单、HTTP/WS 钩子、HTML 注入、JS 运行时及插件提供的扩展 |
| 交互式远程终端 | 删除浏览器终端、编辑器内嵌终端、会话重连、终端中继和 Agent 终端事件下发 |
| 固定内置网页界面 | 保留；仍可改源码重做外观 |
| 明暗模式、配色、背景、首页宽度、默认界面配置 | 保留；这是内置界面的设置，不再支持安装第三方主题 |
| 图表模板、仪表盘拖拽布局、其他在用界面设置 | 保留，并从主题管理入口解耦 |
| 远程文件管理、上传下载、预览、搜索、Monaco 文件编辑 | 保留，拆出独立文件管理入口 |
| 独立命令执行页 /admin/exec、任务结果 | 保留，按“其余先不移除”执行 |
| 在线 SQL、Agent 配置/版本管理、监控、Ping、通知、SSO、2FA、备份、诊断等 | 保留 |
| PWA、多语言、费用/到期/GPU、多数据库及迁移 | 保留 |
| 站点 custom_head/custom_body/customFooterHtml 等已有定制项 | 本轮保留；移除插件注入时不要误删站点自身设置 |

### 0.2 “SSH 控制”的解释与安全结果

本仓库的网页终端通过服务端 WebSocket 与 Agent 中继提供交互式 shell。本轮删除的是这条交互终端能力，不改变操作系统 sshd、22 端口、防火墙或用户在其他 SSH 客户端中的访问。

**保留 /admin/exec 意味着仍能远程执行命令；保留文件管理意味着仍可修改远程文件。完成本计划后，不能宣称系统已经禁止所有远程控制或变成只读监控。** 这是对“其余先不移除”的最小范围解释。若用户后来明确要求禁止所有远程执行，需要另行扩大范围；执行 agent 不得静默删除 exec 或文件管理。

此前“删除整个工作台、Monaco、编码库可大幅降低体积”的建议不适用于这次范围。Monaco 和文件编码依赖必须保留，不能把约 3.09 MB 编辑器分块算作本轮预期节省。

- 整个站点使用一套内置前端；首页、管理、安装和恢复页面均可用。

- 默认 UI、监控、历史、Ping、通知、账户和其他保留功能不因裁剪失效。

## 3. 推荐实现策略

### 3.1 内置界面配置：先小范围解耦

本轮推荐保留现有 ThemeConfiguration 表的 default 行作为内置界面配置存储，实现新的固定界面设置 API。旧模型/目录名称属于内部兼容细节，不等于仍支持第三方主题。

不建议同时重建整套配置数据库。这样可以把工作集中在能力移除，并避免布局、引导状态和备份兼容被一起重写。

建议接口：

| 新接口 | 用途 | 约束 |
| --- | --- | --- |
| GET /api/admin/ui/settings | 读取固定内置界面设置 | 管理员；返回持久值与内置缺省值合并的对象 |
| PATCH /api/admin/ui/settings | 修改给定的设置键 | 管理员；不接受 theme/short/path 作为目标；只更新内置 default 配置 |
| GET /api/public | 保持原接口 | theme 固定为 default，theme_settings 保留现有字段形状，仅返回允许公开的内置配置 |

规则：

- PATCH 采用顶层键合并。数组与对象值作为一个设置整体替换；false、0、空字符串、空数组不能被当作“未提交”。
- 服务端在事务中读取、合并、保存，避免两个页面同时保存不同键互相覆盖；SQLite 锁语义遵循现有连接设置。
- API 仅接受固定内置 schema 的键及应用内部确实使用的保留键。未知键拒绝或返回明确错误，不把遗留插件参数重新暴露为可配置能力。
- 前端复用稳定的 readUISettings/saveUISettings 封装。新 API 已支持部分修改后，不再让多个调用点自行执行全对象替换。
- 新端点可先使用 Gin handler 复用现有身份/审计机制；本轮不要求所有设置 API 再做一轮 RPC 迁移。
- 保留 komari-theme.json 作为内置配置声明与打包元数据，或等价地提取为内部 schema；第一轮优先保留文件以降低 embed 和构建改动。它不得继续驱动外部主题安装或任意页面扩展。
- 不删除 Radix Themes、ThemeContext、ThemeSwitch 或 ColorSwitch。这些是 UI 依赖和本地外观设置。

至少保留这些配置：showIpTagsInCard、showServerListInDetails、backgroundImageUrlDesktop、backgroundImageUrlMobile、offlineServerPosition、customFooterHtml、mainContentWidth、chartDashboardTemplate、_komari_dashboard_v1、_komari_onboarding_v1。执行时以实际 schema 和使用点核对，不仅依赖本列表。

### 3.2 旧主题数据迁移规则

迁移在主库和配置表可用后、公开设置读取和正常路由建立前执行，并保证幂等。

1. 读取旧 theme 值及已有 default 配置，仅读数据库；不加载外部主题的 JS、HTML 或动态 schema。
2. 已存在的 default 设置优先保留。对 default 缺失的受支持键，可从旧活动主题配置中复制；再使用内置默认值兜底。
3. 只迁移内置键和明确保留的布局/引导数据；不复制任意第三方主题参数进入公开设置。
4. 校验输入类型；损坏 JSON 不覆盖原始行，记录问题并回退到可运行的内置默认值。
5. 在同一事务中保存 default 配置、将活动主题固定为 default、记录迁移完成标记。失败不得留下“标记完成但配置未写入”的状态。
6. 已完成迁移时不反复覆盖用户新保存的配置。即便旧备份或 SQL 修改把 theme 改为非 default，运行时也始终使用内置界面，不读取外部主题目录。
7. 原有其他主题行、主题目录和插件文件留作惰性历史数据，不自动删除；新逻辑不执行、不公开提供它们。
8. 引导状态删除/忽略 markets、terminal 等过期步骤，保留 install、notifications；workbench 改为文件管理语义，避免首次进入后台卡在消失的按钮上。

注意 internal/config.GetAs 带默认值可能写入数据库。迁移需要准确判断“键不存在”时，不要先调用会写缺省值的读取函数破坏这个判断。也不要在 dbcore.Initialize 内递归调用 GetDBInstance；迁移显式接收已打开的数据库实例。

### 3.3 文件管理与终端拆分

新页面 /admin/files 复用管理后台的登录保护及 RPC Provider，支持 ?uuid=... 选择节点；未指定时展示节点选择，不自动创建任何终端。

保留 FileManagerPanel 的 uuid 接口；它通过独立文件 RPC/HTTP 工作，不应继续依赖 TerminalSession、terminal request_id 或终端标签状态。

工作台相关组件按“职责”迁移到例如 src/features/files/，而非直接删除 src/pages/terminal：

| 保留并移动/改名 | 处理说明 |
| --- | --- |
| FileManagerPanel、FileEditorDialog、RemoteFileTree | 文件浏览/编辑主体；编辑器内仅删除终端子面板 |
| useRemoteFileService、useRemoteFileUpload、fileManagerApi | 文件协议与传输能力完整保留 |
| FileContextMenu、ConfirmDialog | 文件交互保留 |
| TerminalDialog | 是文件功能也在用的通用对话框，移动并改名为 FileDialog 等 |
| TerminalUploadProgress、transferFormat | 上传进度属于文件功能，保留并改名 |
| monacoSetup | 编辑器依赖，保留 |
| EditorResourceMonitor、TerminalResourceMonitor | 保留资源显示；后者按需改名 NodeResourceMonitor 并迁移选择节点/关闭入口 |
| terminalDefaults、terminalTypes 的共用部分 | 提取编辑器字体、上下文菜单位置等通用类型/常量；不要引入 xterm 类型 |

删除交互终端专属组件：TerminalSession、TerminalSearchBar、EditorTerminalPanel；TerminalWorkspace、useTerminalPage、终端标签/菜单等在文件能力脱钩后删除或仅保留必要的文件页面壳。

FileEditorDialog 的终端菜单项、terminalOpen 状态、快捷键和 EditorTerminalPanel 渲染必须同步移除，不能只删顶层 /terminal 页面。

保留文件打开/保存、多文件标签、编码识别、树搜索、上传/下载/预览、复制/移动/删除/权限操作等现有能力。涉及共享常量、样式和对话框时逐个调整引用。
