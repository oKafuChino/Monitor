## 1. 设计任务与范围

Komari 当前是一个前后端统一构建的 Linux 监控面板。此次任务只重新设计面向访客和节点运维者的前台视觉主题，保留服务端接口、数据模型、认证边界、管理后台的信息架构与行为。主题的目标是「Liquid Kawaii」：用 Apple 式精确层级、克制的二次元色彩和液态玻璃材质，让实时运维数据像悬浮在壁纸上的晶体，而不是覆盖壁纸的白色面板。

主题首先服务于三个场景：快速判断集群是否健康、扫描节点并定位异常、进入单节点查看历史指标。可爱感只用于降低监控压力和表达状态，不能抢走 CPU、内存、磁盘、网络、磁盘 I/O、Ping 等数字的注意力。

### 不在本轮范围内

- 不改变 Go 服务端路由、RPC 方法、数据库 schema、Agent 上报协议、分享链接安全策略或管理员权限模型。
- 不恢复已移除的第三方主题、插件、远程终端、远程命令、文件管理或通知能力。
- 不把设计稿中的视频、Live2D、实时折射理解为当前已有能力。当前主题设置能读取桌面/移动端背景图片 URL；动态视频与 Live2D 作为兼容目标，需要后续单独的能力评估。
- 不把管理后台改造成粉色监控首页。后台继续以高密度、可审计、低装饰为原则；若未来需要统一，只复用颜色 token 和状态语义。

## 3. Liquid Glass 视觉配方

### 3.1 材质分层

每一个前台晶体表面由下至上保持四层，层级越小越轻，不使用厚重实线边框：

1. **背景层**：保留用户图片的构图、色相和动态细节。已有壁纸默认不叠全局明暗遮罩；无壁纸时用低对比粉紫环境渐变提供折射参照。图像不随指针漂移，不为高光裁切人物主体。
2. **体积层**：卡片中部采用极低不透明度的 Blush Crystal 色（浅色读数方案约 `rgba(255, 226, 238, 0.08)`，深色读数方案约 `rgba(38, 23, 46, 0.12)`），分别可在 0.06–0.12 和 0.08–0.18 范围调整。中部保持清透，仅加 0–3px 轻微背景模糊，饱和度 100–108%；不对整卡叠高强度 blur 或 saturate。
3. **折射层**：卡片上沿和迎光侧使用 1px 以内的高光渐变，透明度约 0.28–0.55；边缘可有极窄的粉/青双色色散，宽度控制在 1–2px，避免彩边变成描边。四角采用连续曲率，内侧加非常弱的 Inner Glow，表达切削晶体的厚度。
4. **焦散与阴影层**：底边使用不对称的环境遮蔽和柔和投影，让卡片从壁纸上浮起；卡片内部可有一条低对比的椭圆焦散光。焦散只在静止或交互确认时出现，不能持续呼吸闪烁。

### 3.1.1 设计师可复用的层级参数

以 360px 宽的标准节点卡为样本，虚拟主光源固定在左上方约 35°，只允许悬停时小幅移动。以下长度均为 CSS px 的视觉目标；不要直接视作已经验证过的 CSS 实现。

| 层 | 建议数值 | 作用与限制 |
| --- | --- | --- |
| 中央透光区 | 卡片面积约 80–88%；着色 alpha 0.06–0.12 起步 | 低着色 alpha 不等于物理透光率；叠层后仍需观察壁纸细节 |
| 曲面边缘带 | 向内 6–10px，局部 blur 4–6px | 只在窄边缘形成厚度；不让背景人物面部整体失焦 |
| 迎光切边 | 1px，亮部 alpha 0.35–0.55、背光部 0.06–0.12 | 采用有断续、渐隐的高光，不能四边同亮像描边 |
| 边缘内折射 | 向内 1–3px 的明暗带 | 基础版以明暗梯度模拟；真实背景位移另见可行性说明 |
| 色散 | 粉/青相对偏移 0.5–1px，alpha 0.08–0.14 | 仅覆盖小段迎光边与角部，不覆盖文字和整圈边框 |
| Inner Glow | 内扩 2–4px，粉光 alpha 0.05–0.09 | 表达边缘厚度，中央不泛白 |
| 焦散 | 底部一段窄弧，占宽 18–26%，alpha 0.04–0.08 | 一卡一处；不得在每次数据刷新时扫动 |
| 接触阴影 | 下移 2px，柔化 6px，深紫黑 alpha 0.08–0.12 | 表达贴近屏幕的环境遮蔽 |
| 悬浮阴影 | 下移 10px，柔化 28px，alpha 0.06–0.10 | 只限表面周边，不能演变为整页压暗 |

导航胶囊沿用该配方但弱化焦散；图表卡边缘配方相同，绘图区另有局部可读性层；弹层增加局部底色，不通过层层叠玻璃制造浑浊。切边、焦散和色散属于装饰层，不能拦截点击或进入辅助技术的阅读顺序。

**Web 可行性边界**：背景模糊和渐变高光不能产生真实光学折射。基础版目标是“光学厚度的可信近似”，不承诺物理透镜。真正的背景位移/折射需要额外渲染与兼容验证；静态图可以探索受控贴图，任意跨域图片和视频可能受 CORS/画布污染限制，Live2D 还涉及独立渲染成本。首版不得让页面依赖 WebGL、SVG displacement 或屏幕截图回读才能正常显示。高级折射不可用时保留薄切边、阴影和清晰内容即可。

### 3.2 透明度与可读性

- 透明度由内容密度驱动：导航胶囊和状态芯片更透，指标卡和图表卡更稳；同一层级不要叠加两块浅色玻璃。
- 文字不依赖白底。主指标使用高对比前景色和半粗字重，标签使用带环境阴影的次级色；必要时只在文字后加局部径向背光，半径贴合字块，而不是扩大到整张卡片。
- 图表的坐标、网格和 Tooltip 使用独立的轻暗实色层，折线使用发光但不扩散的晶莹果冻笔触。背景过亮时，先增强图表绘图区的局部对比，再提高整卡不透明度。
- 状态色不只依赖色相：在线附带实心亮点和“Online”文字，离线附带低饱和度和明确标签，告警附带图标/纹理变化，满足色觉差异场景。

**不可读背景的处理顺序**：先使用稳定的明/暗文字方案，再增加字块后方 6–10px 内的局部背光和 1px 紧阴影；仍不达标时，只提高指标读数岛/Tooltip/图表绘图区的底色。正文目标对比度至少 4.5:1，大字号文字至少 3:1，关键图形/焦点边缘至少 3:1。柔光和字重本身不能保证达标，必须检查实际合成像素。对任意高对比视频，“完全透明”与“持续可读”无法无条件同时保证；必须允许小面积读数岛接近实色，仍不压暗整张壁纸、不把整卡刷白。

动态图上的文字不能逐帧黑白反转。首版遵循明确的明/暗模式与稳定局部底色；未来若支持背景亮度取样，应按卡片区域低频更新、带滞回，并在字块可读性不足时使用局部底色兜底。跨域媒体无法取样时使用同样兜底。自动取样不是首版依赖，也不改动后台设置页。

### 3.3 色彩语义

| 语义 | 名称 | 建议视觉角色 |
| --- | --- | --- |
| 主品牌 | Blush Crystal / Liquid Sakura | 导航高光、选中态、主图表强调色；偏粉但不荧光刺眼。 |
| 健康 | Dew Mint | 在线点、正常 I/O、低负载进度条、成功反馈；配深色文字或描边。 |
| 注意 | Peach Gold | 中高负载、数据预热、历史空洞提示；使用琥珀色图标辅助。 |
| 告警 | Raspberry Glow | 高负载、节点异常、错误 Callout；面积小、亮度高、持续时间短。 |
| 中性 | Pearl / Graphite | 标签、轴线、分组、不可用数据；在明暗模式自动反转。 |

以下色值作为色板种子，不是所有背景上的最终文字色：

| Token | 高光/装饰色 | 浅色读数岛的深色对应值 |
| --- | --- | --- |
| Blush Crystal | `#FFE2EE` | `#62394D` |
| Liquid Sakura | `#F497BF` | `#8A345C` |
| Dew Mint | `#9EEBD7` | `#176552` |
| Peach Gold | `#FFD29B` | `#7A4A16` |
| Raspberry Glow | `#FF679D` | `#A41E50` |
| 主文字 / 浅色文字 | `#F7F2FA` | `#281E31` |
| 中性辅助文字 | `#D6CDDF` | `#66596F` |

高光色主要用于发光点、切边和深色绘图区；浅色绘图区换用深色对应值。粉色品牌色不等于故障色：告警必须同时包含“高负载/异常”文案和三角图标。在线仅表示连接状态，不能等同 CPU、磁盘或业务完全健康。

避免将 Radix 的任意 accent 颜色直接当作材质颜色。颜色切换仍保留现有主题设置，但 Liquid Kawaii 的状态语义必须优先于装饰 accent。

### 3.4 曲率、间距和排版

- 页面容器采用连续曲率 Squircle；导航、状态芯片、筛选器是胶囊，指标/节点/图表容器是大圆角连续曲面。圆角按层级递增，不让每个元素都变成相同的圆。
- 以 4px 为基础节奏，页面内边距优先使用 `rem`，让用户放大字体后仍能换行和重排。节点卡内容保持紧凑，操作命中区至少 44px。
- 首选平台系统字体并开启 optical sizing；大标题略收紧字距，小标签保持接近 0 或轻微正字距。数字使用等宽或 tabular figures，避免实时刷新时宽度跳动。
- 主指标、单位、更新时间分别有清晰层级，不用全大写、粗描边或大号贴纸制造“二次元”效果。可爱感来自小面积糖果色、圆润图标和状态微表情式的光点。

| 用途 | 字号 / 行高 | 字重与字距 |
| --- | --- | --- |
| 全局关键数字 | 28–32 / 34–38px | 600，数字等宽，拉丁字距 -0.02em |
| 节点名称 | 16 / 24px | 600，字距 0，最多两行 |
| 卡片数值 | 16–18 / 24px | 600，数字等宽，单位 12–13px |
| 标签/正文 | 13–14 / 20px | 500，字距 0 |
| 时间/辅助信息 | 12 / 18px | 450–500，不能靠极低透明度减弱 |

SF Pro Rounded 只作为圆润精密的气质参照；不假定非 Apple 系统有该字体，不分发无授权字体。中文使用系统中文无衬线字形，字距不照搬拉丁负值。Lucide/Radix 图标沿用现有资源，16–20px 视觉大小、统一圆端线条；操作热区独立于图标尺寸。

### 3.5 状态语义矩阵

| 状态 | 视觉处理 | 数值与行为 |
| --- | --- | --- |
| 在线且采样有效 | Mint 实心水珠 + 在线 | 显示真实值；0 是有效数字 |
| 高负载 | Peach 60–79.9%，Raspberry ≥80%，伴随数值 | 仅沿用现有 UsageBar 阈值，是视觉提示，不创建告警/通知系统 |
| 节点离线 | 中性色空心点 + 离线 | 当前速率显示“—”；历史值若保留，标记最后更新时间 |
| 浏览器与服务失联 | 中性色连接图标 + 数据连接中断 | 区分站点连接和节点状态；不能把缓存值继续标成实时 |
| I/O 预热 | Peach 小圆弧 + 等待采样 | 无进度百分比，不编造剩余秒数 |
| I/O 未支持 / 已禁用 | 中性色图标 + 各自文案 | 不以错误红色惩罚正常配置，也不显示 0 B/s |
| I/O 不可用 | Peach 感叹号 + 采集不可用 | 说明当前数据不可用，不能推断硬盘故障 |
| 无历史 / 断档 | 空图文案 / 曲线断开 | 不跨缺失补线，不填成零 |
| 无搜索结果 | 原搜索框保持焦点，显示清除筛选 | 不能与“尚无节点”混用 |
| 分享失效 | 清除节点数据后的中性状态页 | 不保留敏感信息作为淡出残影 |

## 4. 主要界面构图

### 4.1 顶部微透导航胶囊

现有 `NavBar` 的品牌、GitHub、明暗、颜色、语言和登录入口保持不变，只改变空间关系：

- 导航悬浮在页面上方，左右留出壁纸呼吸区；品牌位于左侧，右侧控制项收纳在一条低高度液态胶囊内。
- 胶囊不做纯白长条。顶部高光、底部环境遮蔽和内侧粉晶光足以表达边界；滚动时保持轻微的背景穿透。
- 登录/设置入口使用樱花色单色系渐变填充、对比清晰的文字，降低面积，保持为工具性操作；GitHub、主题、语言为低层级透明按钮。Mint 留给健康状态，焦点态用清晰外环而非放大弹跳。
- 移动端压缩品牌副标题和控制项，保留站点名、主题/语言与登录入口；隐藏元素仍通过菜单提供，不能让胶囊横向溢出。

### 4.2 全局流动数据概览

首页总览对应 `Index.tsx` 的时间、在线数量、区域、流量和网络速度五个状态卡：

- 采用一块宽的“水面”容器，内部是 5 个无独立底色的数据区，避免玻璃叠玻璃。大屏在线数量、速率、流量优先排列，区域和时钟次之；移动端采用两列网格，速率/流量必要时跨两列，不把关键状态藏入横向轮播。
- 在线数量是视觉锚点：左侧放 Dew Mint 状态点和在线/总数；无数据时使用静止空态，不模拟增长。当前没有首页在线率历史来源，不添加“24 小时健康趋势”或未经定义的 SLA。
- 流量与速度用上下行两条短色带区分，颜色来自同一语义组，数值使用等宽字形。区域数和时间使用较低层级，避免与实时负载竞争。
- 总览设置入口保留在容器右上角，弹出层沿触发点展开，采用更深一层的晶体材质；开关即时反馈，不在设置弹出时改变页面布局高度。
- 现有 HTTPS/连接 Callout 采用局部状态岛：Raspberry Glow 只覆盖图标和短标签，主体内容仍透明，让壁纸可见。连接失败文案应描述“实时数据连接中断”；当前数据刷新走 RPC2，不能仅沿用旧 WebSocket 命名作为准确诊断。

总览数据口径沿用当前实现并写在说明中：流量、网速和区域来自当前可见在线节点，不代表全站全部历史流量、账期流量或所有已部署区域。五项显隐继续读取既有本地偏好；重新排序不改变汇总公式。

### 4.3 节点筛选与服务器节点晶体卡片

`NodeDisplay` 的搜索、分组、网格/表格切换和结果统计组成“控制水带”，节点卡组成下方晶体阵列：

- 搜索框是带内嵌放大镜的流体胶囊，输入焦点出现 Liquid Sakura 环形高光；分组选择使用横向滚动的标签胶囊，当前项以浅粉晶体填充表达。
- 网格卡片采用 24px 视觉圆角、轻量折射边、悬浮环境阴影。卡片上层是地区旗帜、节点名、在线状态、Ping 入口和消息；下层是 OS、CPU/内存/磁盘进度、网络速度和流量。小型嵌入区圆角 12–16px，胶囊用半高圆角。浏览器不支持连续曲率时采用普通圆角近似，不宣称 border-radius 就是真正 Squircle。
- 状态点与卡片标题对齐，在线为薄荷色“水珠”，离线为低饱和 Graphite/Peach Gold；消息告警只在卡片右上角形成一小块莓红光，不把整卡染红。
- UsageBar 从厚色矩形改为窄胶囊轨道：轨道透明，填充带内部高光和极短尾光；健康、注意、告警的阈值沿用现有 60/80 语义，但增加数字百分比和状态文字。
- 磁盘 I/O 当前已在详情/图表与分享摘要呈现，首页 `Node.tsx` 尚未展示。本方案建议在宽卡底部新增一个可换行的“读 / 写”数值对，沿用现有公开报告；不要用无最大值的速率画百分比条。采样间隔只在说明中展示，不占主信息位。`warming_up`、`unsupported`、`unavailable`、`disabled` 显示各自文案，不显示 0 B/s。历史双线图继续保留在详情，断网历史保留空洞。
- 表格视图保留给大量节点和键盘用户：行背景使用玻璃薄片，列标题和状态芯片保持对齐，不强迫表格复制卡片的装饰。网格/表格切换只改变布局，不重置搜索、分组或滚动位置。

### 4.4 单节点详情与图表

- 详情页左侧服务器列表是窄而深的晶体侧栏，当前节点用 Liquid Sakura 的内嵌光标表示；分组标题使用半透明条，不使用厚分隔线。
- 顶部硬件信息、实时摘要与图表卡遵循“由稳到透”的层级：硬件摘要更稳，实时摘要更透，图表绘图区最清晰。
- 图表卡的折线颜色固定为可区分的薄荷、樱花、蜜桃、莓红序列；线条边缘带小范围光晕，网格极细。Tooltip 是贴近指针的深色晶体，不遮挡整个图表。
- 可拖拽排序的图表使用抓取点和轻微抬升表示可移动，落位时采用一次性弹簧回弹；不要让每条折线同时动画，避免实时监控产生视觉噪声。
- 磁盘 I/O 双线图、GPU 多设备图和 Ping/丢包图共享同一图表材料，但图例清楚标出“状态/缺失/断线”三种语义。

绘图区的每条线有 1.5–2px 锐利实线核心，外侧光晕宽 4–6px、alpha 不超过 0.12；密集多序列图关闭光晕。读/写和上/下行同时以文字及实/虚线区分，颜色在切换节点与缩放时间范围后不变；折线使用不产生伪峰值的插值方式。负载数值、CPU 百分比、字节速率不共用一个无单位纵轴。Tooltip 至少列出时间、序列名、实际值、单位与必要的聚合口径，不用装饰光晕覆盖数据点。

既有图表模板顺序、尺寸和管理员保存权限保留；主题不自动覆盖旧模板。节点详情支持深链刷新、返回列表后恢复筛选及可用的滚动锚点；视觉转场不可取代路由导航和键盘焦点管理。

### 4.5 临时分享站

分享站保持独立 bundle、无登录后台依赖和现有安全路由。采用“轻液态”版本：一块主节点晶体、少量统计晶体、明确到期信息和历史图表。不要加入主站导航、管理员入口、壁纸注入或会暴露分享凭证的动画。在线/离线、撤销、过期和 I/O 不可用状态应优先保证可读性。

分享站目前仅允许其独立归档中的 JS/CSS 静态资源，CSP 也没有开放任意视频与第三方媒体。因此首版背景使用 CSS 静态色场，复用材质参数即可；不复用主站的壁纸请求、主站 Provider、字体下载或图片资源路径。品牌相同不要求网络依赖相同。

## 5. 动效与 Motion Blur 场景

### 5.1 动效原则

遵循 Apple 的可中断弹簧模型：动效从屏幕当前值开始，手势释放时继承速度，新的输入可以立即改目标；不锁住输入、不等待上一段动画结束。普通出现/消失使用临界阻尼（damping 约 1.0、response 约 0.3–0.4）；只有拖拽/快速甩动后的落位使用轻微回弹（damping 约 0.8）。

运动模糊只服务于速度感和方向感：静止状态晶体边缘锐利，运动期间在移动方向上拉出 4–12px 的低透明高光尾迹，回到静止后立即收回。模糊优先作用于装饰层和阴影，不模糊数值、状态文字、图表轴线或用户壁纸主体。

这里的 response 是弹簧响应参数，不是固定播放时长；不同库参数不可直接照抄。后续实现用现有 Motion/Vaul 的实际 API 对齐感受，并确保手势速度、目标变化和退出路径连续。普通 hover 可用短过渡，拖拽抽屉必须能被重新抓取。

### 5.1.1 运动设计标尺

| 交互 | 位移/形变上限 | 动力学与视觉目标 |
| --- | --- | --- |
| 按钮按下 | 缩放至 0.98 | 触下立即反馈，释放恢复；不让文字挤压变形 |
| 节点 hover | 上移 2px，不扩大整卡 | 约 140–180ms；仅精确指针设备启用 |
| 弹出菜单 | 触发点向外 6–8px | damping 1.0、response 0.25–0.30s；无多次弹跳 |
| 服务器切换 | 内容位移 8–16px，容器保留 | 旧内容约 80–100ms 淡出，新内容约 140–180ms 淡入；数据可先到，不人为等待动画 |
| 抽屉程序打开 | 沿实际进入方向 | damping 1.0、response 0.30–0.35s |
| 抽屉手势释放 | 回弹位移上限约 8px | damping 0.85–0.90、response 0.30–0.40s；继承释放速度 |
| 图表排序落位 | 抬升 3–4px，缩放最多 1.01 | 释放后单次收敛，不能震荡折线；键盘有等价排序方式 |
| 进度读数更新 | 数值直接更新，填充约 160–220ms 收敛 | 占用率不得因弹簧超调短暂超过真实百分比；正常更新不加运动残影 |
| 减少动态 | 无位移、无形变、无视差 | 0–120ms 淡化；保持焦点和状态变化清楚 |

**方向残影规范**：以屏幕坐标中的卡片运动方向为准，尾迹在运动反方向延伸。基础方案是复制一段无内容的高光弧，经位移、拉伸和 opacity 形成 1–2 道衰减尾迹；这是方向速度线的近似，不把普通各向同性 `blur()` 称作真实快门模糊。严禁复制整卡文字作为残影。建议低于 600px/s 不出现，600–1400px/s 从 0 增至 6px，超过 1400px/s 最长 12px；alpha 上限 0.10–0.14，减速后 80–120ms 内消失，反向时先收回旧尾迹。阈值是原型调参起点，移动端默认最多 6px，低性能档关闭。

### 5.2 快速滑动节点列表

1. **普通列表沿用浏览器原生滚动和惯性**。不把每张节点卡变成拖拽物，不拦截滚轮，不增加网格吸附，也不对主页面重写橡皮筋。
2. 用户向上快速滑动时，卡片随滚动向上移动，顶部迎光边变得稍亮，尾迹向下延伸。插画背景保持稳定的视口锚定，卡片像晶体滑过画面；若未来开启视频，视频按自身时间播放，不随滚动快进、后退或重启。
3. 卡片中心仍透出底层画作。折射近似只发生在边缘薄带；正文、CPU 数字、网速和坐标保持锐利。背景不追加速度模糊，否则与视频本身运动叠加容易眩晕。
4. 用户减速或停止后，边缘在 80–120ms 内收束为 1px 微光，所有卡片静止，无余震、呼吸、持续流光。触摸立即反向时，尾迹随当前速度更新，不等待旧动画播放完。
5. 原生边界反馈由浏览器处理；约 10px 手势识别阈值、1:1 跟手、速度投影和自定义橡皮筋仅用于明确可拖动的抽屉/图表排序，不套用到浏览列表。
6. 减少动态模式下关闭装饰尾迹，滚动仍保持用户熟悉的系统行为。键盘翻页不附加大范围动画；装饰不能拦截链接、选中文字或屏幕阅读器。

### 5.3 切换服务器节点

- 从当前详情切到另一节点时，左侧列表的当前光标沿同一路径移动，内容区从当前卡片的视觉锚点向新卡片交叉过渡；不采用整页向左飞出再从另一方向进入。
- 节点切换的标题、UUID 对应内容和加载状态一同更新；数据可用的卡片先出现，尚未取得的新图表显示局部静止骨架。新节点数据缺失时立即显示“等待采样/不可用”，不把旧节点数据暂时套在新节点上，也不按固定延迟逐个放行卡片。
- 快速连续点击时取消前一个目标并从当前呈现值重定向；图表数据请求可以取消，但视觉容器不能闪白或回到页面顶部。

### 5.4 路由、抽屉与弹出层

- 状态设置、节点筛选弹层从触发点向外展开，微缩放和高光 opacity 同步变化，形成“材质到场”。背景模糊半径保持稳定，避免逐帧重算滤镜；小型装饰层的模糊变化只作为高性能增强。
- 详情侧栏在移动端以底部抽屉呈现，拖拽跟手、释放继承速度、边界橡皮筋；打开和关闭沿同一条路径返回。
- 模态抽屉才允许低强度 scrim（黑色 alpha 约 0.06–0.10），目的为提示焦点归属；不额外大范围压暗壁纸。抽屉内容依靠自身局部可读底色。非阻塞的 Tooltip、筛选层和图例不暗化背景；模态具备焦点约束、Esc 关闭、关闭后焦点返回。

### 5.5 数据变化反馈

- 正常实时更新仅更新数值和进度长度，不给所有卡片每两秒做光泽扫过。只有在线状态变化或用户主动操作出现一次边缘亮度反馈；禁止持续呼吸动画造成“所有东西都在报警”的感觉。
- 在线/离线变化用一次短促的状态点放大与颜色落位；告警使用一次方向明确的边缘闪光和图标变化，不震动整张卡。
- 图表新点从当前时间轴位置接入，历史线不重新播放；断网恢复时以空洞连接新旧段，不能用动画掩盖采样缺失。

## 6. 背景融合、响应式和无障碍

- 背景图片继续使用现有桌面/移动 URL 设置。设计上为未来视频/Live2D 预留背景层接口概念：背景、环境取样、玻璃表面和前景交互分层，但本阶段不承诺实现视频播放或背景上传。
- 不通过整屏压暗来解决对比度。采用卡片局部环境遮蔽、文字背光、绘图区局部底色和动态前景色；高对比壁纸必须保留可辨认的原始细节。
- `prefers-reduced-motion: reduce`：替换滑动、弹簧、残影、视差为短交叉淡化或静态状态；`prefers-reduced-transparency: reduce`：玻璃提高不透明度并降低/关闭 blur；`prefers-contrast: more`：改用近实色表面和明确对比边缘。
- 键盘焦点必须有高对比环；状态、图表线条、在线/离线和 I/O 状态同时提供文字/图标/形状信息；触控命中区至少 44px；文字放大时卡片可换行，不能截断关键数字。
- 深色模式不是把粉色整体变黑。深色玻璃使用 Graphite 基底、樱花和薄荷高光，保证白色数字不出现光晕溢出；浅色模式避免大面积纯白发灰。

无障碍偏好优先于材质透明度。减少透明度/高对比度模式可以使用柔和、接近实色的粉灰或石墨表面，这是独立的可读性模式，不是默认大白磨砂。相关媒体查询并非所有浏览器都支持，后续前台外观菜单应提供本地“清晰阅读/减少动态”覆盖项，不需要增加后台页面或服务端字段；当地偏好损坏时退回安全默认值。

### 6.1 视频 / Live2D 扩展的设计条件

视频只有在静态材质方案通过验收后再单独排期。未来背景视频需默认静音、内联播放、提供静态封面和可见暂停按钮；自动播放失败直接使用封面，不反复弹提示。离开页面/标签页隐藏时停止装饰运算并暂停视频；减少动态偏好默认展示静态封面。图像/媒体加载失败使用内置静态色场，不能让内容消失。

壁纸从选择到播放的完整链路尚未设计进当前后台 schema。Live2D 还需要模型资源、运行库、交互冲突、授权和移动耗电评估，不能等同一个可直接加载的视频文件。本文只规定两类背景之上的视觉共存原则。首版不会注入第三方播放器，也不通过自定义 HTML 绕过固定设置与分享站限制。

### 6.2 性能与降级

| 档位 | 材质与背景 | 运动 |
| --- | --- | --- |
| 标准（首版默认） | 极低着色 + 细切边 + 轻阴影；背景最多一次解码/呈现，图表局部清晰底色 | transform/opacity 为主，静止时无常驻装饰循环 |
| 增强（验证后启用） | 有限边缘折射近似、焦散；未来可选视频背景 | 仅视口内少数卡片的速度尾迹，不叠加全页滤镜 |
| 节能/无滤镜 | 去掉 blur、色散、焦散，保留细边与局部对比底色；媒体用封面 | 关闭尾迹，使用短淡化或直接切换 |
| 清晰阅读 | 近实色读数区、高对比前景与焦点 | 按用户减少动态偏好执行 |

不创建每卡一个视频/Canvas、不在滚动时读回整个屏幕、不为玻璃新增数据轮询。暂停离屏装饰，避免给数百个节点永久设置合成层；大节点列表是否虚拟化以实际测量决定，不能牺牲搜索、焦点和浏览器查找。

后续性能验收目标：参考设备 60Hz 下交互稳定接近 60fps，单帧预算约 16.7ms；120Hz 为增强目标而非承诺。用 12、60、200 个节点，分别叠加高对比图片和未来 1080p 视频测试，记录设备/浏览器、长帧、输入反馈与内存，不只录一段流畅演示。若滚动持续掉帧，按“关色散/焦散 → 关尾迹 → 减少背景滤镜 → 暂停视频”的顺序降级。无需真实折射也必须保持产品可用。

## 7. 组件落地优先级（供后续实现拆解）

### 7.1 防止主题影响后台

当前 `main.tsx` 的 Radix Theme、`ThemeContext`、`global.css` 同时服务前后台，`appearance` 与 `color` 也使用共享本地设置；仅改全局 `--card`、`--background`、`.dark` 或 `.rt-Card` 就可能改变后台。后续主题必须限定在公共布局根（现有 `.km-layout` 可作为边界），使用独立的 `liquid-*` 语义 token；不要重设全局 Radix 配色默认值为粉色。

弹层通常通过 Portal 渲染到根节点外。前台专属 Portal 需要显式携带主题作用域或独立容器，不能靠全局菜单/Toast 选择器强行覆盖。共享组件采用明确的前台变体或作用域继承，不改后台默认样式。管理登录、安装、数据库迁移、恢复页面都保留现状。

现有明暗和配色偏好保留兼容；新增的阅读模式/动画档位可以使用独立前台本地键，不能自动重写后台共享偏好。本方案不需要修改 `internal/uisettings`、后台 appearance schema 或 API。视频配置若需要新增字段，必须在以后单独定义范围。

| 现有位置（相对 `komari-web/`） | 后续设计责任 | 保留边界 |
| --- | --- | --- |
| `src/pages/_layout.tsx` | 公共背景层、主题根、导航与内容宽度 | 现有图片 URL、移动端回退、宽度配置 |
| `src/components/NavBar.tsx` | 悬浮胶囊和移动工具菜单 | 登录跳转、语言、主题、外链功能 |
| `src/pages/Index.tsx` | 总览信息优先级和连接状态 | 汇总口径、五项显隐、数据刷新 |
| `src/components/NodeDisplay.tsx` / `Node.tsx` / `NodeTable.tsx` | 筛选胶囊、卡片、表格、窄屏信息密度 | 搜索字段、分组、离线排序、权限、链接 |
| `src/components/UsageBar.tsx` | 胶囊轨道、状态色与确定性进度 | 数值阈值和真实百分比，后台使用者不变 |
| `src/pages/instance/index.tsx` / `LoadChart.tsx` | 节点切换、图表框架与材质 | 路由 UUID、数据清空/取消、模板和权限 |
| `src/components/DetailsGrid.tsx` | 硬件摘要和 I/O 读数层级 | 各状态与单位，不能全盘换算为百分比 |
| `src/components/NodeMetricChart.tsx` / `src/share/share.css` | 分享站轻材质和图表可读性 | 独立 bundle、无主站上下文依赖 |
| `src/contexts/*` / `src/utils/diskIO.ts` | 作为数据契约参照 | 不为动画提高采样或轮询频率，不改鉴权 |

### 7.2 推荐实施顺序

**P0：材质与 token**：先在公共前台作用域定义背景层、玻璃层、折射边、环境遮蔽、状态色、焦点环、动效减少模式；使用代表性静态素材评审，不改全局 Radix 默认值。验收后得到可复用的材质规范。

**P1：首页主路径**：`NavBar`、首页总览、`NodeDisplay` 控制水带、`Node` 卡片、`UsageBar`、空态和 Callout。先验证壁纸穿透、在线/离线、I/O 状态和移动端布局。

**P2：详情与图表**：节点侧栏、`DetailsGrid`、`LoadChart`、`NodeMetricChart`、拖拽图表落位和快速节点切换。重点验证实时更新不闪烁、数据缺失不造假、动效可中断。

**P3：分享站和边界**：独立分享 CSS、到期/撤销/离线空态、深色移动端、减少动态/透明度/高对比度验收。

**P4：精修**：字体 optical sizing、细微色散、焦散强度、性能预算和浏览器差异。可选背景取样、视频/Live2D、真实折射另设探索任务，不成为首版阻塞项。任何精修都不能牺牲监控读数、首屏加载或后台稳定性。

未来设计稿至少交付：首页桌面明/暗各一张、移动首页、节点详情、打开的节点抽屉、分享页、连接中断、I/O 不可用和清晰阅读模式；动效另交付“快速滚动—停止”“A→B→C 连续节点切换”“抽屉中途反向”三段演示。此轮仅交付本文及文字线框，没有生成 UI 原型或修改业务代码。
